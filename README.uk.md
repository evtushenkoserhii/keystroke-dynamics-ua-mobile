# KDUA-Mobile: український корпус клавіатурного почерку на смартфонах із сенсорами

[English version](README.md)

498 сесій набору тексту від 71 особи на 56 пристроях Android, записаних
клавіатурою, написаною для дослідження: кожне натискання й відпускання клавіші,
дотик, який його викликав, і рух апарата з частотою 200 Гц під час набору.
Український текст, розкладка ЙЦУКЕН.

Версія 1.0, зібрано з 16 вересня до 26 жовтня 2026 року. DOI: *буде присвоєно
під час публікації.*

---

## Чим цей корпус відрізняється

У більшості корпусів клавіатурного почерку одна людина набирає на одному
апараті, тож людина й апаратура невіддільні: класифікатор, який розрізняє два
записи, може насправді розрізняти два телефони, і з даних цього не видно.
Тут конфаундинг розбито з двох боків навмисно:

- **14 пристроїв мають двох і більше різних людей**, що дає 63 пари різних людей на тій самій апаратурі;
- **11 осіб є на двох пристроях**, тож шаблон можна перевірити там, де його не навчали.

Ще дві властивості, яких у порівнянних корпусах зазвичай немає:

- **Умову виміряно, а не припущено.** Кожен учасник набирав те саме речення сидячи, стоячи й з телефоном на столі. Гіроскоп самого апарата записував, чи він справді лежав: із 90 сесій із такою вказівкою 74 вимірювані, і лише 38 справді виконані. Вказівка і спостереження - це різні стовпці.
- **Порядок контрбалансовано.** Три умови переставляються латинським квадратом 3×3, який детерміновано обчислюється з ідентифікатора учасника, тож позиція кроку й умова не злиті.

Чим цей корпус не є: підставою для висновків про населення. 71 студент одного
українського університету, 75 записів із 82 - до 20 років, одна мова, одна
розкладка.

## Де що лежить

| | |
|---|---|
| Zenodo, за DOI | повний пакет одним архівом, із сенсорами, 411 МБ, і зразок на 1,5 МБ |
| цей репозиторій | код, документація, зразок, протокол перевірки, три малі таблиці й `key_events.csv.gz` |

Теки `data/sensors/` у репозиторії немає: 389 МБ у 495 файлах - це більше, ніж
варто тримати в Git, а Git LFS не рятує, бо один клон витратив би третину
безкоштовної місячної квоти трафіку. `data/features/` теж немає, бо
`code/features.py` відтворює її точно. `checksums.sha256` описує повний пакет,
тому перевірка клону робиться з ключем `--quick`:

```
python code/verify.py --dataset . --quick
```

## Швидкий старт

```python
import pandas as pd

s = pd.read_csv("data/sessions.csv")
k = pd.read_csv("data/key_events.csv.gz", dtype_backend="numpy_nullable")
g = pd.read_parquet(f"data/sensors/{s.session_id[0]}.parquet")
```

`code/load.py` і `code/load.R` роблять те саме, але з урахуванням пасток.
Перед будь-яким використанням даних прочитайте `docs/quality.md`, розділи 1 і 4:
там чотири фільтри, потрібні кожному аналізу цього корпусу, і один із них -
різниця між наданою вказівкою і фактичною умовою.

## Базовий результат

Разом із даними опубліковано навмисно просту методику: логарифми медіан
диграфів і часів утримання, масштабована манхеттенська відстань, без навчання
й без параметрів. На фіксованому протоколі зі `splits/verification_protocol.json`
вона дає рівну помилку **22,2 %**, а різниця між самозванцями на тому самому
апараті (23,6 %) і на іншому апараті (22,2 %) становить 1,4 пункта.

Саме за цією різницею і слід дивитися. Методика, яка працює значно краще проти
самозванців на інших апаратах, ніж проти самозванців на тому самому, читає
апаратуру, а не людину. Відтворити:

```
python code/features.py      --dataset .
python code/make_protocol.py  --dataset .
python code/baseline_eer.py   --dataset .
```

## Відтворення пакета із сирих експортів

```
python -m pip install -r code/requirements.txt
python code/convert.py --input <тека з архівами> --output . --strict
```

Конвертація детермінована: ті самі архіви дають ті самі таблиці на будь-якій
операційній системі й за будь-якої розкладки тек. Байтові суми з
`checksums.sha256` на іншій машині відтворити неможливо, бо pyarrow вписує свою
версію у підвал кожного файлу Parquet. `fingerprint.sha256` - це хеш, який
відтворюється, і він обчислюється так, що його може перерахувати будь-хто, маючи
лише опублікований пакет:

```
python code/verify.py --dataset .
```

Еталонне значення для версії 1.0:

```
00330347a3e47af885486916fd89306f73a7c5baf5124d672075726785babcf8  overall
```

Повний порядок складання пакета з нуля: `convert.py`, `features.py`,
`make_protocol.py`, `make_sample.py`, і наостанок `verify.py --write`, який
перезаписує обидва файли хешів по всьому, що на той момент існує.

## Межі, про які варто знати до початку

- Умову "телефон на столі" виконано в 38 сесіях із 74 вимірюваних. Відбирайте за `motion_active_fraction`, ніколи за `hold_style`.
- `pressure` постійний у 470 сесіях із 498: більшість цифрових перетворювачів Android не має датчика тиску. Це не ознака.
- 100 сесій не мають перевірки руху: 54 давніші за лічильники, 46 на апаратах без гіроскопа.
- 31 запис із 82 зроблено на позиченому телефоні, і частина цих людей має також власний запис, який зв'язати з цим нічим. Для аналізу самозванців беріть 51 запис з `own_device = own`.
- Сесії вільного тексту публікують клас кожної клавіші, але не її ідентичність. Скелет довжин слів лишається відновлюваним, і це виміряно в `docs/privacy.md`, розділ 3.
- Поділ треба робити за `person_id`. Поділ за сесіями або за записами учасників протікає, бо 11 осіб мають по два записи.

Усе з цього переліку розписано в `docs/known_issues.md`. Нічого з нього не
знайшов рецензент: усе знайдено нами й опубліковано навмисно.
